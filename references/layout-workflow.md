# 扫描报告的版式重建

## 页面与内容模型

为每页记录原 PDF 宽高（pt）、渲染图宽高（px）、页类型、OCR 词框、表格框、行列线、合并单元格、图片及签章位置。换算分别用 `x_pt=x_px*page_width/image_width`、`y_pt=y_px*page_height/image_height`，不能默认所有页面都是同一 A4 尺寸。

建议每个单元格保存独立身份：源文件、源页、行列区间 `[r0,c0,r1,c1]`、像素边界、中文原文、英文译文、核对状态。表格结构与译文独立保存，人工校正后不要再次用初始 OCR 覆盖。

扫描件的歪线、印章、文字笔画容易被误判为分隔线。通过原图确认真正的表格边界，不能机械地把检测出的所有线条变成行列。空白剩余区域按原件保持合并或分列，不凭美观重新设计。

## Word 构造选择

- 优先利用可靠的 PDF 转 Word 结果或原始可编辑模板，再替换译文；其合并和定位仍需检查。
- 必须重建时，使用固定列宽、明确单元格宽度和合并关系的原生表格。合并后复查 `tblGrid`、`gridSpan`、`vMerge` 与实际单元格宽度，避免所有列挤到同一位置。
- 固定版式可用 `w:tblpPr` 设置相对页面的表格位置，正文用定位文本框。所有形状 ID 必须在文档内唯一，合订时重新编号。
- 一页一节有利于按原图定位，节起始方式和纸张尺寸必须逐节设置；表格后的段落也会占空间，要避免意外产生空白页。
- 固定行高可能裁掉用户后续增加的文字；译文先量测后渲染，交付说明应提示大幅编辑后需重新检查分页。不能宣称增加行列后仍自动保持原版式。
- 保留的扫描背景只包含照片、标志、签名、印章等需要的部分；已替换的中文正文和表格线应清理，避免双层文字/双重边框。清理不能误删签章，尤其黑色印章不能只按红色筛选保留。

## 容易遗漏的核对点

- 封面 OCR 可能把补充说明识别为第二个报告号：不能循环匹配后叠加同一字段。
- 原件已有英文副标题或双语声明时，保留原有英文，中文译文放到原中文位置；避免把原英文再叠印一次。
- 表格表头、“1#–3#”样品范围、日期中的手写日数、4.1/4.2.1 等条款、正负偏差、小数点、μm 与 mm 均需单独核对。
- 检测结果可能是跨行合并判定或多层样品编号；以视觉结构和单元格身份对齐，不能只凭行号推断所有页的列值。
- 批注可能在打印/渲染时展开为页边气泡并缩小页面。要求保持照片页大小时，不用批注塞入整段标签翻译；使用独立索引对照文件，或按用户要求在原位置重建文字。
- 合订报告可以复用已核对的单独报告，但还需验证合并后的节尺寸、分页、图片关系和形状 ID。渲染文本一致只能辅助判断，无法证明照片和印章相同。

## 环境与隐私

从当前环境的依赖发现工具查找 Python、PDF、Word 渲染运行时；不要写死某次会话的缓存目录。无需为复用 skill 安装与任务无关的软件。只在必要时申请具体依赖或路径权限。

包含注册资料、产品标签和签章的文档默认在本地处理。用户要求翻译并不自动授权上传至第三方翻译/OCR 网站；优先本地工具，确需外部处理时先说明具体服务和上传范围。
